# German pages (i18n)

The site is English first. Forty pages have a German counterpart under `/de`: the core a
German buyer needs (product, platform, the main detections, partner pages, three DACH
industries, pricing, security and data protection, cameras). Guides, comparisons, the
glossary, use cases and legal pages stay English. `docs/INTERNATIONAL-EXPANSION.md` has
the market research behind the choice.

**German copy is AI-drafted and has not been reviewed by a native speaker.** Get a
native review before any German outreach points at these pages.

## How it fits together

| Piece | Where | What it does |
|---|---|---|
| Pair registry | `lib/i18n.ts` → `translations` | The one list of English ↔ German pairs. Everything below reads it. |
| hreflang | `generatePageMeta()` | Looks the path up in the registry and emits `alternates.languages` on both sides. Pages never write hreflang by hand. |
| OG locale | `generatePageMeta()` | `de_DE` for any `/de` path. |
| Page language | `PageShell` | Derives the locale from `path`: German breadcrumbs, German CTA band, `inLanguage: 'de'`, content wrapped in `lang="de"`. |
| Chrome strings | `lib/ui-strings.ts` | Header, footer, breadcrumbs, CTA band, FAQ heading, cookie banner. |
| Header and footer | `site-header.tsx`, `site-footer.tsx` | German navigation (German pages only) and German labels on `/de` paths. |
| Language menu | header top bar | Goes to this page's counterpart, or the German/English home when there is none. |
| `<html lang>` | `DocumentLang` + `Content-Language` header | The root layout is shared by every route, so the static HTML says `en`. German content carries `lang="de"` on its own wrapper, the document root switches after hydration, and `next.config.js` sends `Content-Language: de` for `/de/*`. |
| Sitemap | `app/sitemap.ts` | The `de` group is `germanPaths` from the registry. |
| Stale check | `scripts/check-translations.py` | Fails on a pair whose file is missing; flags a German page whose English source changed since it was stamped. |

## Adding a German page

1. Pick the German slug. Use the terms below, lowercase, `ae/oe/ue/ss` for umlauts and ß.
2. Add the pair to `translations` in `lib/i18n.ts` with `sourceHash: ''`.
3. Create `app/de/<slug>/page.tsx` from the English page (rules below).
4. Stamp it: `python3 scripts/check-translations.py --stamp /de/<slug>`.
5. Run the verification loop plus `python3 scripts/check-translations.py`.

## When an English page changes

`check-translations.py` reports its pair as **stale**. Carry the change into the German
page, then stamp again. Stamping without updating the German page defeats the check.

## Writing a German page

**Structure.** Mirror the English page: same sections, same components, same images
(identical `src`), in the same order. The skeleton is the one in `docs/ADDING-PAGES.md`:

```tsx
const pageMeta = {
  title: '…',        // 50 source characters or fewer
  description: '…',  // 70 to 163 characters
  path: '/de/…',
};
export const metadata = generatePageMeta(pageMeta);   // no hreflang, no locale: derived
…
<PageShell {...pageMeta} faqs={faqs} breadcrumbs={[{ label: 'Plattform', href: '/de/plattform' }, { label: '…' }]}>
  …
  <FaqSection items={faqs} locale="de" />
</PageShell>
```

Exactly one `<h1>`. Breadcrumbs start at the German home automatically; parent crumbs
link to German parents where they exist. Translate every string, including `alt` text,
`caption`, `label`, `facts`, `eyebrow`, `ctaProps`, schema names and descriptions, and
the HTML inside any `dangerouslySetInnerHTML` string.

**Links.** An internal link goes to the German counterpart when the registry has one,
otherwise to the English page. `/book-a-demo` and `/roi-calculator` stay English.

**Facts: translate, never add.** Every claim on a German page must be a claim the
English page already makes. No new figures, customers, certifications, response times
or prices. The hard rules in `CLAUDE.md` apply unchanged:

- Pricing: only "ab 5 US-Dollar pro Kamera und Monat" and "die meisten Kameras liegen
  zwischen 20 und 90 US-Dollar pro Kamera und Monat". Prices stay in US dollars; no
  euro conversion. Billing is per instance per month, quoted per site.
- PDPA, DSGVO (GDPR), SOC 2 Type II and ISO 27001 are **in Vorbereitung, nicht
  erteilt**, target end of 2026. Never present one as held.
- Footage: "in Amazon S3, in der AWS-Region, die den Standorten des Kunden am nächsten
  liegt". **Never name a region, city or country** (not Frankfurt, not Germany).
- No statement about a named competitor. Where the English page names one, leave that
  passage out of the German page rather than translating it.
- German standards (DIN 77200, DIN EN 50518, DIN EN IEC 62676, VdS 2366/3138/2172,
  DSGVO, § 4 BDSG, the DSK Orientierungshilfe Videoüberwachung) may be named as context
  a German reader recognizes. Camzify holds none of them; never imply it does.
- US-specific material (US state rules, US wage figures) is either framed plainly as US
  context with its source kept, or left out. Do not localize a US figure into a German one.

**Prose in shared components.** Faux product UI stays English because the console is
English-only: `ProductShot` screenshots, the `*Mockup` components,
`InteractiveChecklistDemo`, `DemoFrame`. Explanatory *sentences* must be German. When a
component renders English prose with no prop to override it (`SceneObservation`, some
`SectionVisual` variants, `QuoteEstimator`), do not use it on a German page: choose a
`SectionVisual` variant without prose, or write the equivalent German markup inline.
Components with a `locale` prop (`FaqSection`, `BrandStrip`, `CTABand`) get
`locale="de"`. `DeploymentPlan` takes a German `heading`.

**Style.**
- Address the reader as *Sie*.
- Use German quotation marks „…“ and a decimal comma.
- Use a spaced en dash (` – `) where English uses an em dash; never use an em dash.
- Keep sentences as plain as the English. Bold the one definition sentence in a hero
  lede, as the English pages do.

## Known limits

- The static HTML's `<html lang>` is `en` on German pages until hydration (see the table
  above). Moving to per-locale root layouts would fix it at the cost of restructuring
  every route; not worth it at forty pages.
- `/book-a-demo`, the pricing quote form, the newsletter and the legal pages are English.
  German pages say so where they link to them.
- There is no Impressum. A site aimed at German buyers is usually expected to carry one;
  that is a legal decision for the business and counsel.
